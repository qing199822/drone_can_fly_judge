# 裁判软件人物活动边界缺陷：人物会跑出城区

> 反馈对象：组委会（官方 `robocup/control_actor.py`）
> 底稿：Gitee `robin_shaun/XTDrone` `robocup/control_actor.py`
> 反馈人：（队伍名） 日期：2026-10-11

---

## 一、结论（三句话）

1. `control_actor.py` 的**人物活动边界**（`x∈[-50,130]`、`y∈[-60,60]`）**明显大于城区实际范围**（实测 `x∈[-35.1,106.3]`、`y∈[-45.1,77.0]`）；
2. 人物被"发现"后会以 **2 m/s 逃逸**，因此会**跑到城外**并在那里停留；
3. 实测人物最终停在 **`x = 150`**，**已超过脚本自己的 `x_max = 130`** —— 说明**逃逸路径没有执行边界检查**。

后果：无人机按赛题在**城区内**搜索，而目标已跑到城区外 → **无法完成"消除"**，一支队伍的分数会被卡死在"发现分"上。

---

## 二、证据（实机实测）

### 2.1 边界值与城区范围不一致

```python
# control_actor.py:44-51
# self.x_max = 50.0      ← 作者原本的意图（城区内），已注释
# self.x_min = -10.0
# self.y_max = -20.0
# self.y_min = -30.0
self.x_max = 130.0       # ← 实际生效
self.x_min = -50.0
self.y_max = 60.0
self.y_min = -60.0
```

城区真实范围（由本轮 `robocup.world` 中 **107 个静态模型**的 `<pose>` 统计得出）：

```
x ∈ [-35.1, 106.3]      y ∈ [-45.1, 77.0]
```

即边界在 **+x 方向多出约 24 m、-x 方向多出约 15 m**。

### 2.2 人物实际跑到了边界之外

```
actor_0 (150.0,   3.2)      actor_3 (150.0,  -8.5)
actor_1 (150.0, -48.9)      actor_4 (150.0,  -4.5)
actor_5 (  0.97, -50.0)
```
（坐标为 `/gazebo/get_model_state('actor_<i>')` 实测；`actor_2` 已判定消除故返回 0,0）

**4 个人物停在 `x = 150`，而 `x_max = 130`** → 越界 20 m（恰好等于 `escape_distance = 20.0`，疑为逃逸步长未做钳制）。

### 2.3 人物初始落点本身是合理的

同一轮地图生成器给出的 6 个初始落点**都在城内**：

```
[[52,-18], [53,-35], [72,-2], [-3,-27], [35,-31], [-11,38]]
```

所以**不是生成器的问题，是"跑出去"的问题**。

### 2.4 逃逸机制（驱动力）

```python
self.escape_speed = 2.0            # 逃逸速度 2 m/s
self.escape_distance = 20.0        # 无人机进入 20 m 内触发
self.escape_trigger_speed = 1.0    # 且无人机速度 > 1 m/s
# 逃逸仅在"裁判系统报告过该人物"之后解锁（reported → escape_requested）
```

一旦被判定"发现"，人物就开始持续逃跑；一轮任务 600 秒、速度 2 m/s，**足以跑出城区并停留在地图边缘**。

## 三、影响面

| 影响 | 说明 |
|---|---|
| 分数 | 队伍能拿到"发现分"（50/目标），但**拿不到"消除分"**（100/目标）—— 对本队实测：6 发现 + 1 消除后卡住，剩余 **500 分**取不到 |
| 公平性 | 该行为**对所有队伍一致**（组委会跑同一份脚本），但会显著降低比赛的可完成度与区分度 |
| 稳定性 | 人物停在 `x=150` 已接近/超出地面平面边界，长时间停留可能触发物理或渲染异常 |

---

## 四、建议修法（供参考）

1. **把边界收到城区范围内**（或改成从 world 自动推导城区包围盒）：
   ```python
   self.x_max, self.x_min = 106.0, -35.0
   self.y_max, self.y_min =  77.0, -45.0
   ```
2. **让逃逸路径同样受边界约束**（当前越界 20 m 说明未钳制）：在计算逃逸目标点时把结果 `clip` 到 `[x_min, x_max] × [y_min, y_max]`；并在**实际写入位姿前**再做一次钳制，避免步长/漂移造成越界。
3. （可选）把边界做成 ROS 参数（`~x_min` 等）或从 world 推导，便于不同地图复用。

## 五、本机为了联调所做的本地对照（不影响官方代码）

为避免改动官方文件，我们在**副本**上打了个补丁（`--actor-in-city`）：只把上述 4 个边界值改成城区范围，其余逻辑一字不改，并对最终位姿做一次范围钳制。**官方原文件保持不动**，便于随时切回官方行为做 A/B。
