# 模拟裁判系统（官方链路）—— 可复现跑法

> 本机 = **组委会/裁判机**：起随机地图 + Gazebo + 6×PX4 SITL + 6×MAVROS + 6 个人物 + 裁判计分。
> 另一台电脑 = **算法机**：通过 ROS 组网加入，**只订阅**话题、发布控制与人物坐标，接受裁判打分。
> 依据：官方《RoboCup 无人机仿真赛双机通信官方指导文档》§3.1 主机启动流程。
>
> ⚠️ **职责边界（老师 2026-10-10 明确）**：队伍提供的一键脚本**不包含**启动 Gazebo world 仿真与裁判软件，
> **这两块由组委会启动**。官方裁判端代码 = <https://gitee.com/robin_shaun/XTDrone/tree/master/robocup>。
> 因此本文的 `start_official_judge.sh` 是**本机用来模拟组委会那一侧**的；队伍侧只应使用 `start_sim_only.sh`（默认不起 world/裁判）。
> 详见 §7.1，计分公式口径差异（必读）见 §7.3。


## 1. 一条命令起裁判端（本机）

```bash
cd /home/wangtao/robocup_fly/zzu_fly
bash start_official_judge.sh --display=headless --map=random --seed=20261009 --round-limit=600
```

| 参数 | 说明 |
|---|---|
| `--display=headless\|gui` | 默认 headless（省资源；GUI 用于人工看画面） |
| `--map=random\|stock` | **random（默认）**：每轮用官方随机化算法生成地图；stock：用官方自带 `robocup.world` |
| `--seed=N` | 固定随机种子，便于复现同一张图 |
| `--round-limit=SEC` | 只是提示，到时手动结束 |
| `--no-actors` / `--no-score` | 分别跳过人物运动 / 裁判计分 |
| `--mirror` | 额外起 `referee_mirror.py`（实时打印每个目标的"找到/跟踪进度"） |
| `--ros-ip=IP` | 显式指定本机对外 IP（默认自动探测） |
| `--inspect-only` | 只做前置检查并打印将启动的节点，不启动任何进程 |

**流程**（脚本内部顺序，与官方文档一致）：

```
[0] 前置检查（px4 / mavlink_sitl_gazebo 包、robocup.launch、world）
[1] 清残留（tools/kill_stale_sim.py，含 actor/score_cal）
[2] 显式启动 roscore（监听 0.0.0.0:11311）
[2b] 生成随机地图 → 覆盖 Tools/sitl_gazebo/worlds/robocup.world
[3] 只起 Gazebo 世界 → 等世界就绪（模型数连续 3 次稳定）
[4] 逐架（官方 single_vehicle_spawn_xtd + mavros，端口 2454i/3458i）拉起 6 架并逐架确认 connected
[5] 6× 官方 control_actor.py + score_cal.py（可选 referee_mirror.py）
```

> ⚠️ 顺序有讲究，别改成"一条 `roslaunch robocup.launch` 了事"：
> 官方那份 launch 会**并发 spawn 6 架**，而城市世界本机要几十秒才加载完，必然出现
> `Spawn service timed out waiting for entity to appear ... entity already exists`。
> 另外 `roscore` 必须**先单独起**：让 `roslaunch` 自动拉 master 时，`gazebo_ros_api_plugin`
> 只会注册日志服务、不注册 `spawn_sdf_model`/`get_model_state`。

## 2. 验收清单（本机自检）

```bash
source /opt/ros/noetic/setup.bash && source devel/setup.bash
export ROS_MASTER_URI=http://192.168.12.101:11311      # 本机跑则用 localhost 亦可

# 世界就绪：应 ≥100 个模型
python3 tools/world_probe.py 10

# 6 架 MAVROS 全部 connected: True，mode: "AUTO.LOITER"
for i in 0 1 2 3 4 5; do echo -n "drone$i "; rostopic echo -n1 /typhoon_h480_$i/mavros/state | grep -E 'connected|mode'; done

# 6 个人物在动（约 10 Hz）
pgrep -c -f control_actor.py            # 期望 6
rostopic hz /actor_0/cmd_motion | head -3

# 裁判实时计分
rostopic echo /score          # 未找到目标时 = 传感器扣分（常见 -5）
rostopic echo /left_actors    # 形如 "[0, 1, 2, 3, 4, 5]"
rostopic echo /time_usage
cat logs/official_round_*/score.txt | tail -1
```

## 3. 算法机接入（另一台电脑）

```bash
# 网络
ip -br addr show <有线网口>            # 应为 192.168.12.102/24
ping -c3 192.168.12.101               # 通
sudo ufw disable                       # 官方要求

# ROS 环境（容器需 --network host）
export ROS_MASTER_URI=http://192.168.12.101:11311
export ROS_IP=192.168.12.102
source /opt/ros/noetic/setup.bash

# 连通性 + 双向验收（官方 §2.2）
rostopic list | head                   # 应能看到 /typhoon_h480_0/... 与 /score
rostopic echo /test_msg                # 主机侧: rostopic pub /test_msg std_msgs/String "data: hi" -r 1
rostopic pub /test_msg2 std_msgs/String "data: hi_from_slave" -r 1   # 主机侧 echo 验证

# 起算法栈（只在裁判机发布的图上工作）
cd <算法机上的 zzu_fly>
bash start_sim_only.sh --master-uri=http://192.168.12.101:11311 \
     --num-drones=6 --no-rviz --ros-ip=192.168.12.102
```

> 算法机必须先 `catkin build` 一次（`darknet_ros_msgs` / `ros_actor_cmd_pose_plugin_msgs` 等自定义消息要能在对端解析）。

## 4. 常见故障对照表（都是本项目实际踩过的）

| 现象 | 根因 | 处置 |
|---|---|---|
| PX4 日志 `Error: Unknown model ''`，启动脚本返回 256，MAVROS 永不 connected | XTDrone 的 `single_vehicle_spawn_xtd.launch` 把 `<env PX4_SIM_MODEL>` 写在 `<node>` **外面**，roslaunch 忽略 | `bash tools/setup_official_chain.sh` 的 `[6b]` 已自动修补（幂等） |
| PX4 永远 `Waiting for simulator to accept connection on TCP port 4560` | `GAZEBO_PLUGIN_PATH` 指到了空的 `build/px4_sitl_default/build_gazebo/`；v1.11 插件其实在 `Tools/sitl_gazebo/build/` | 启动器已同时加两个路径；自研链路则靠 source `setup_gazebo.bash` |
| `Spawn service timed out ... entity already exists` | 并发 spawn 撞上尚未加载完的世界 | 用本启动器（先世界 → 后逐架） |
| gzserver 卡死、CPU 100%、无任何输出，Gazebo 服务不注册 | `model://` 资源本地找不到，gzserver 去连**在线模型库**（本机国际直连是 SYN-SENT 挂死，不是快速失败） | 模型全部本地 + `GAZEBO_MODEL_DATABASE_URI=""`；`start_referee.sh` 还会预检 `cardboard_box/cessna/casual_female` |
| 人物启动失败，日志 `new node registered with same name` | 上一轮的 `control_actor.py` 残留没被清理 | `tools/kill_stale_sim.py` 已补上 `control_actor.py`/`score_cal.py`/`referee_mirror.py` 等特征 |
| 算法机 `rostopic list` 看不到主机话题 | 主机没导出 `ROS_IP`（对端解析不到本机 hostname），或防火墙没关 | 用本启动器（自动导出 `ROS_IP`+`ROS_MASTER_URI`）；`sudo ufw disable` |
| 播报的坐标整体偏 ~17 m，裁判判不到"发现" | 出生点布局：本机自建布局是 `(-17,-3)` 系，官方 `robocup.launch` 是 `(0,-3)` 系 | 算法端用 `start_sim_only.sh --env-profile=official`（自动把 `spawn_origin_x` 设为 0） |
| 想快速判断环境是什么样子 | — | `python3 tools/check_env_profile.py --num-drones=6`（画像判定 + 缺失话题失效面 + 出生点校验） |

## 5. 一轮完整比赛（按官方"最多 3 次、每次 ≤10 分钟"）

```bash
# 每次尝试前重新随机地图；三次取（和/3 或 最好一次，规则文本自相矛盾，见交接文档）
for k in 1 2 3; do
  bash start_official_judge.sh --map=random --round-limit=600 --display=headless
  # 算法机接入并跑完一次；结束后 Ctrl-C，或另开终端：
  #   rostopic echo /score      记录最终分
  python3 tools/kill_stale_sim.py
done
```

当前实现会把分数写到 `logs/official_round_<时间戳>/score.txt`。

### 7.1 职责边界（老师 2026-10-10 明确）

> "**不包含启动 gazebo 的 world 仿真和裁判软件哈，这两个组委会来启动**"

| **参赛队算法** | **参赛队** | 本文的 `start_sim_only.sh`（**默认 `--no-score`，不起裁判** ✓） |

### 7.4 双机通信口径逐条对照

官方依据：《RoboCup 无人机仿真赛双机通信官方指导文档》§1.4 / §3.1 / §3.3。

| # | 官方要求 | 本机实现 | 对齐 |
|---|---|---|---|
| 1 | 容器 `--network host` | 宿主机直跑（天然 host 网络） | ✅ 等价 |
| 2 | 主机 `ROS_MASTER_URI=http://<主机IP>:11311` | 脚本自动 `http://$(hostname -I 首个IP):11311` | ✅ |
| 3 | 主机 `ROS_IP=<主机IP>` | 自动导出 `ROS_IP`，并 `unset ROS_HOSTNAME` | ✅ |
| 4 | **先单独起 `roscore`（保持终端不关）** | `[0/7]` 显式起 `roscore -p 11311` | ✅ **且本机必需**：让 `roslaunch` 自动拉 master 会导致 `gazebo_ros_api_plugin` 只注册日志服务 |
| 5 | 另开终端 **`roslaunch robocup.launch`** | 默认「先世界 → 后逐架」（`tools/launch/robocup_judge_gazebo.launch` + ×6 `robocup_judge_drone.launch`） | ⚠️ **有意偏离**（见 §7.5）；严格复刻命令见 §7.5 |
| 6 | 人物控件随世界一起起 | 官方 `control_actor.py` ×6（sha256 已校验） | ✅ |
| 7 | 裁判软件 | **官方原版 `score_cal.py`**（收发方向一致） | ✅（见 §7.3） |
| 8 | 两台机器都关防火墙 | `/etc/ufw/ufw.conf: ENABLED=no` | ✅（checklist 第 7、8 项） |
| 9 | 双向验收 `/test_msg`、`/test_msg2` | 步骤见本文 §3 | ⚠️ 待第二台机器实测 |
| 10 | 选手侧 `roslaunch your_package your_algorithm.launch` | `start_sim_only.sh`（内部依次 roslaunch，等价） | ✅ |
| 11 | 主机/选手 IP = 192.168.12.101/.102（网线直连） | 当前 Wi-Fi `192.168.0.x`（本机 .3） | ⚠️ 网段不同；"同网段 + 互 ping + 双关防火墙"效果等价 |
| 12 | 队伍脚本**不含** world 仿真与裁判软件 | `start_sim_only.sh` 默认 `--no-score`，不启动 gzserver/PX4/MAVROS/裁判 | ✅ |
| 13 | `roslaunch robocup.launch`（不带包名，靠 `ROS_PACKAGE_PATH` 找到） | 我们显式 `roslaunch px4 robocup.launch`（同一份文件） | ✅ |

### 7.5 严格复刻官方流程（可选）

若要**逐字**照官方（不做"先世界后逐架"的加固）：
```bash
# 终端1
roscore
# 终端2（ROS_PACKAGE_PATH 需含 PX4 树与 Tools/sitl_gazebo）
roslaunch px4 robocup.launch          # == 官方 roslaunch robocup.launch
```
本机实测：能解析出 20 个节点（gazebo + 6×sitl + 6×spawn + 6×mavros），但**6 架 spawn 会因城市世界尚未加载完而超时**
（`SpawnModel: timed out waiting for entity to appear ... entity already exists`）——这就是默认走拆分布局的原因。
其他机器性能足够时可直接用官方这条。
