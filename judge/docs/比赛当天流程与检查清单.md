## 3. 算法侧启动命令（已按现场修正）

```bash
JUDGE_IP=<裁判机当前 IP>      # 例：192.168.12.101
MY_IP=<本机 IP>

docker run -d --name player_algo \
  --network host \
  -e ROS_MASTER_URI="http://${JUDGE_IP}:11311" \
  -e ROS_IP="${MY_IP}" \
  --device /dev/nvidia0 --device /dev/nvidiactl --device /dev/nvidia-uvm --device /dev/nvidia-modeset \
  -v /usr/lib/x86_64-linux-gnu/libcuda.so.1:/usr/lib/x86_64-linux-gnu/libcuda.so.1:ro \
  -v /usr/lib/x86_64-linux-gnu/libnvidia-ml.so.1:/usr/lib/x86_64-linux-gnu/libnvidia-ml.so.1:ro \
  -v /usr/lib/x86_64-linux-gnu/libnvidia-ptxjitcompiler.so.1:/usr/lib/x86_64-linux-gnu/libnvidia-ptxjitcompiler.so.1:ro \
  zzu_fly_algo:v2 sleep infinity

docker exec -it player_algo bash -lc 'cd /root/ZZU_FLY && bash 1.sh'
```

**两点已修正**（见 `docker/run_player.sh`）：
1. **不再挂载宿主源码** ✗ —— 现场用镜像内自带的 `src` + **已编译 devel** ✓
   （挂载会造成"源码新、devel 旧"⇒ 必崩 ✗，此前踩过）
2. **GPU 用 `--device` + 挂驱动库** ✓（本机无 `nvidia-container-toolkit`，`--gpus all` 会失败 ✗；
   实测 `cuda_available: True` ✓ 备选：`--gpus all`）

## 5. 高频坑速查（本地实测踩过的）

| 症状 | 根因 | 处置 |
|---|---|---|
| 容器内 `rosnode list` 空、窗格全连不上 | `ROS_MASTER_URI` 指向了**过时的 IP** | 用当前 IP；本机自测用 `127.0.0.1` |
| 飞机停 POSCTL 不飞 | XTDrone **通信桥没起** ⇒ 无 setpoint 流 ⇒ PX4 拒 OFFBOARD | 确认桥接窗格成功（`/xtdrone/*/cmd_vel_flu` 有数据） |
| `Arming denied: high throttle` | PX4 油门位置解锁检查（本地演练已用环境开关绕过，**仅本地**） | 赛场用组委会环境，不适用我们的补丁 |
| `road_follow` 无输出 | ① 任务不在 `ROAD`/`TRANSIT_TO_REGION`（按设计静默 ✓）② 或 torch 缺 CUDA 库退 CPU | 先看 `mission/stage`；再确认 `LD_LIBRARY_PATH` 含 torch/lib |
| 解算报"無法獲取有效深度" | 深度有效量程 ≈10 m，而目标在 20~40 m 外 | 保持 **5~9 m** 站位 |
| 人物永远遇不到 | 本轮实测 6 个人物**全被钉在 x=150**（边界钳制，组委会赛前不修） | 最东侧巡逻区域东延到 x≈130~160 |
| 窗格看着起了其实没起 | 容器内 `roslaunch <file>` **必须带包名或先 cd 到 launch 目录** | 统一用 `1.sh` / 或带包名 |
